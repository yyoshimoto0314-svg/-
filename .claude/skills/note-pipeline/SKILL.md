# note記事パイプライン

引数：テーマ。空なら「おまかせ」。

## 準備
1. 今日の日付（JST）を `TZ=Asia/Tokyo date +%F` で取得し、テーマから英小文字の slug を決める。
2. 出力先 `output/<日付>/<slug>/` を作る。
3. 前回作った `note-article` スキルが使える環境なら、リサーチと下書き投稿はその手順を優先して使ってよい。
   その場合も、成果物は下記のファイル名で出力先に保存すること。

## 工程（各工程はサブエージェントに任せる。CEO は自分で本文を書かない）
1. **リサーチ**：`note-researcher` に テーマ・`config/brand.yaml`・出力先 を渡す → `research.md`
2. **執筆**：`note-writer` に出力先を渡す → `draft.md`
3. **校正**：`note-editor` に出力先を渡す → `article.md`, `edit_notes.md`
4. **QA**：`qa-reviewer` に出力先を渡す → `qa.md`
   - FIX：指摘を該当担当（多くは `note-editor`）に渡して直させ、もう一度 QA。最大2回まで。
   - REJECT：テーマを変えるか、人間に判断を仰ぐ。
5. **報告**：タイトル・文字数・QA判定・人間の確認ポイントを短く報告する。

## やらないこと
- note への「公開」はしない。下書き保存まで（ブラウザ操作できる環境で、人間が許可した場合のみ）。
